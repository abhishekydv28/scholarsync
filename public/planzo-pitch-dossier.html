1. Executive Summary & Problem Statement

Engineering colleges impose rigid, high-friction operational constraints on students: mandatory 75% attendance criteria with debarment consequences, simultaneous lecture and laboratory timetables, university examination weightage spreads (5 units per course), and external viva pressure.

Generic productivity applications (Google Calendar, Notion, Apple Reminders) treat student time as isolated blocks, lack academic awareness, and generate cognitive guilt when assignments or study sessions are missed. PlanZo is purpose-built as an intelligent Student Operating System that combines regulatory 75% attendance protection, mathematical load balancing, dynamic guilt-free schedule recalibration, and an AI campus copilot.

3. Mathematical Core & Specialized Algorithms

Algorithm 1: 75% Attendance Regulatory & Safe-Bunk Math

Eliminates student guesswork and debarment notices through exact regulatory mathematics:

Overall Attendance Percentage:
P = (A / T) × 100

Consecutive Classes Needed to Reach 75% (Recovery):
Classes Needed = ⌈(0.75 × T - A) / (1 - 0.75)⌉ = ⌈3T - 4A⌉

Safe Bunk Allowance (Classes that can be missed safely):
Safe Bunks = ⌊(A - 0.75 × T) / 0.75⌋ = ⌊(4A - 3T) / 3⌋

Algorithm 2: Cognitive Load & Mental Bandwidth Balancing

Prevents student burnout by weighting task density against available daily recovery windows:

Bandwidth Density Score:
Score = min(100, [ Σ (Duration_i × Weight_i) / Total_Available_Hours ] × k)

• Lab Sessions: Weight = 4 to 5 (High fatigue factor)
• Theory Lectures: Weight = 3 to 4
• Self-Study / DSA: Weight = 2 to 3
• Buffer / Chill Blocks: Weight = 1 (Restorative)
• Trigger: When Score > 75%, system injects an automatic 20-min Chill Zone.

Algorithm 3: Dynamic Schedule Recalibration (Greedy Slack Interval)

When a study block is delayed or missed, PlanZo avoids the "domino effect" of schedule collapse:

1. Identifies missed task and reason.
2. Scans evening slack intervals (free time slots before 11:30 PM).
3. Shifts non-critical items and strictly protects the 11:30 PM sleep window.
4. Injects an immediate 20-minute cognitive buffer.

Algorithm 4: 80/20 Pareto Curriculum Pruning

Isolates high-frequency recurring 10-mark and 14-mark university exam questions from the past 5 years of papers, generating high-yield 72-hour accelerated study roadmaps.

Algorithm 5: Sound Synthesis & Pentatonic Frequency Modulation

Generates mathematical chime frequencies without MP3 assets:
C5 (523.25 Hz) → D5 (587.33 Hz) → E5 (659.25 Hz) → G5 (783.99 Hz) → A5 (880 Hz)
Modulated via Web Audio API ADSR (Attack, Decay, Sustain, Release) exponential volume envelopes.

4. API Architecture & Performance Characteristics

The API relies on a Server-Side Proxy Pattern that ensures security, speed, and continuous availability:

  • Zero API Key Exposure: The Gemini API key is encapsulated inside the Node.js backend. Client inspection in browser DevTools reveals zero third-party tokens.
  • Structured JSON Output: The /api/recalibrate and /api/syllabus-planner endpoints enforce responseMimeType: 'application/json', guaranteeing parseable data without markdown wrapping.
  • Context-Enriched Ingestion: Each prompt to /api/chat injects the student's real-time attendance margin, semester, branch, and cognitive density score.
  • Dual-Tier Fallback: If the cloud model is unreachable or offline, the server executes a deterministic heuristic engine, ensuring zero crashes and continuous uptime.
